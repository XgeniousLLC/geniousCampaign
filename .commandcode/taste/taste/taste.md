# Taste
- Specifies UI/UX changes by attaching annotated reference screenshots and expects the implementation to match them closely (layout, labels, selected/default states). Confidence: 0.75
- Wants operational limits/quotas (e.g. an account's daily send cap) to be user-editable from the UI rather than fixed or hardcoded. Confidence: 0.5
- Expects new or derived features to reuse the same full capability and UI patterns as their existing counterpart rather than a stripped-down one-off (e.g. a subsequence branch's "Build steps" should surface the same step editor/template picker as the main sequence). Confidence: 0.6
- Expects child/derived entities to inherit settings from their parent instead of re-prompting for the same configuration (e.g. a subsequence should send from the parent sequence's selected email accounts, not ask you to pick senders again) — duplicate/inheritable config UI in a child should be removed and replaced with an explanatory note. Confidence: 0.6
- Verifies changes by manually testing the app in the browser: asks the agent to start the local dev servers (web + API) and provide the running URLs and a checklist of what to try. Confidence: 0.6
- Reports problems and requests in very terse, sometimes misspelled one-liners describing only the observed symptom (e.g. "loca server not loading", "run the app in lcoally", "i have reply to an email , that reply showing in all others email invidiual page as well", "when change status to not intested it does nothing"), often attaching a screenshot of the affected screen, and expects the agent to diagnose and fix them autonomously without back-and-forth clarification. Confidence: 0.75
- Expects the real local dev flow to work as documented (`npm run dev` with dev-mode behavior: hot reload, dev-only hints like demo credentials) and rejects production-build workarounds as a substitute for "running locally". Confidence: 0.55
- When asked to finalize or apply fixes, expects the agent to automatically stage changes (excluding `.commandcode/`), commit with a detailed conventional-commit message, and push to the remote repository (defaulting to `origin/dev`). Confidence: 0.9
- Expects database migrations to run automatically on application startup (e.g., `npm run db:migrate --workspace apps/api && npm run start:prod --workspace apps/api`) so new schema changes are applied without manual intervention. Confidence: 0.8
- Prefers per-account third-party credentials stored in the database over shared global env vars (e.g. each Google account connect should use its own saved client ID/secret, not a single GOOGLE_OAUTH_* env set). Confidence: 0.75
- Prefers a clean, Gmail-like email reading experience: individual messages should be collapsible (collapse to a sender/timestamp summary row), and quoted/forwarded/older content must stay hidden behind a "•••" dots toggle instead of rendering inline, so a thread reads cleanly. Default state should reflect "recent first": when opening a thread, every message except the two most recent should start collapsed (threads with ≤2 messages open fully). Confidence: 0.65
